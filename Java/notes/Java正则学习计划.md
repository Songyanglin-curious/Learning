# Java 正则学习计划

已有正则基础。专题目标是能选择合适的文本处理方式，解释 Java 的匹配结果，并用需求和反例审查 AI 生成的正则。以 [廖雪峰 Java 正则教程](https://liaoxuefeng.com/books/java/reg-exp/index.html) 检查覆盖，以 Java SE 17 的 [Pattern](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/regex/Pattern.html) 和 [Matcher](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/regex/Matcher.html) 核对行为。

## 学习路线

用工单号 `TASK-0042` 串起三个问题。先定义文本规则和业务边界，再看 Java 如何执行规则，最后验证调用方式与模式组合起来是否满足需求。

| 阶段 | 学习内容与切入方式 | 达成依据 |
| --- | --- | --- |
| 1. 什么时候用正则 | 对照查找固定文本、验证工单号格式、从日志提取编号、解析 JSON 日志和查询工单状态。对应教程简介与匹配规则，按疑问复习语法。 | 能解释何时选字符串操作、正则、解析器或业务代码，以及格式校验能保证什么。 |
| 2. Java 怎么匹配 | 复用同一个工单模式，对比纯编号、以编号开头和中间出现编号的输入。理解源码字符串转义、可复用的 Pattern、有状态的 Matcher、matches / lookingAt / find 和捕获结果。再用相邻字段观察分支、贪婪／非贪婪与回溯；用提取结果引出搜索和替换。 | 能预测调用结果、命中范围和捕获内容，并能解释改变入口、量词或边界时结果为何变化。 |
| 3. 怎样审查 AI 生成的实现 | 把工单号需求写成预期行为，在实际 JDK 上运行候选模式及其调用代码。覆盖正常值、空输入、长度边界、额外字符、Unicode 数字和日志里的多处命中。提取时断言数量、范围和分组，替换时断言完整输出。 | 能从需求独立写出预期，给出一个能区分正确与错误实现的反例，并定位差异来自模式、标志位、调用方法或输入处理。 |

常规 API 按需查阅。遇到动态拼接、替换文本或复杂边界时，再补模式转义、替换转义和标志位。性能部分理解重复和分支为何可能产生大量回溯，实际测量按场景安排。

专题结束时，按选型、匹配模型和审查方法整理已形成的判断，记录实际运行结果和待确认问题。实验只用于验证具体疑问。

## 起点

字段规则暂定为大写 `TASK-` 加四位 ASCII 数字。用字面操作找固定前缀，用正则描述编号形状，用 JSON 解析器读取结构化日志字段，用业务查询确认编号是否存在。接下来用相同的模式分别验证整个字段和扫描日志，观察调用方法如何改变匹配结果。
