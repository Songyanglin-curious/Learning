# Java 加密与安全 · 第 13 章学习总结

这一章讲的是**如何保护数据内容，如何验证数据，以及如何建立对通信对方的信任**。在开发里，同一个需求往往要拆开看。下载一个配置包，你可能要用 HTTPS 保护传输，用数字签名确认发布者。下载完成后，如果文件放到共享目录里还需要保密，就要另外保护文件本身。

## 各节解决什么问题

| 教程小节                     | 应该记住什么                                                                                                                                                                                                     |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **13.1 编码算法**      | Base64、十六进制把字节表示成文本，方便传输或显示。知道编码规则就能还原。Java 用 `Base64`或 `HexFormat`。                                                                                                     |
| **13.2 哈希算法**      | SHA-256 等算法把任意长度的数据变成固定长度的摘要。可以把文件摘要和**从可信渠道取得的摘要**比对，检查文件是否一致。Java 用 `MessageDigest`。                                                              |
| **13.3 Bouncy Castle** | Java 密码学库，可以作为 JCA 的 Provider，为 `MessageDigest`、`Cipher`、`Signature` 等标准 API 提供额外的算法实现。遇到特定算法或格式的兼容要求时再查。                                                     |
| **13.4 HMAC**          | 用**共享密钥**和消息生成校验值，接收方用同一把密钥重新计算，验证消息有没有被改过、是否由掌握这把密钥的一方生成。典型场景是 Webhook 校验。Java 用 `Mac`。                                                 |
| **13.5 对称加密**      | 同一把秘密密钥用于加密和解密，适合文件、备份、字段和网络流量。AES 是算法，CBC、GCM 是工作模式。**AES-GCM 同时提供保密和篡改检测**。Java 可查 `Cipher`或更高层的加密库。                                  |
| **13.6 口令加密**      | PBE 把人输入的口令派生为密钥，再加密需要读回的数据，例如用密码保护归档文件。**网站登录只需要验证密码**，用带盐、计算成本可调的密码哈希，例如 Argon2id，Java 项目可查 Spring Security `PasswordEncoder`。 |
| **13.7 密钥交换**      | DH、ECDHE 让双方通过交换公开信息，各自算出同一个共享秘密，再派生实际使用的密钥。**密钥交换本身无法确认对方是谁**，TLS 还需要身份验证。                                                                     |
| **13.8 非对称加密**    | 以 RSA 的加密用途为例，发送者用接收方的公钥加密，接收方用私钥解密。实际保护大块数据时，通常由对称加密处理正文，再用公钥机制保护数据密钥。                                                                        |
| **13.9 数字签名**      | 私钥对数据签名，持有**可信公钥**的人可以验签，确认数据有没有被修改，以及签名来自哪把私钥。正文仍然可读。Java 用 `Signature`。                                                                            |
| **13.10 数字证书**     | CA 签署一份包含**域名、公钥、有效期**等信息的数据。浏览器验证证书链和域名后，才知道该用哪把公钥来验证服务器。自签名证书也能用于 TLS，客户端需要事先建立对它的信任。                                        |

## HTTPS 把这些能力串了起来

浏览器访问 Nginx 时，在常见的 **TLS 1.3 完整握手**中，双方先用临时密钥对协商共享秘密。浏览器验证证书，确认公钥可以代表访问的域名，再用这把公钥验证 Nginx 对本次握手做的签名，确认当前对端持有对应私钥。握手之后，**HTTP 数据由派生出的对称流量密钥保护**。

这对应到部署上，证书和私钥配在 **TLS 终止点**。Nginx 如果在这里解密请求，浏览器到 Nginx 的保护就到此为止。Nginx 转发到 Spring Boot 时，后面那段是否加密，取决于上游连接自己的配置。

## 开发时怎么用这章知识

* **保护传输** → 查 TLS 配置，确认每一段连接和证书部署的位置。
* **验证登录密码** → 查 `PasswordEncoder`，数据库保存密码哈希。
* **验证文件或消息来源** → 查对接协议，看双方共用密钥做 HMAC，还是用公钥验签。用公钥验签时，还要知道公钥从哪里可信地取得。
* **保护以后还要读回的数据** → 查存储加密或 AES-GCM，同时确认谁能解密，以及密钥和数据是否处在独立的权限边界里。
