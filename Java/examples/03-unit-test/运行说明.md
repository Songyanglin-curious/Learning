# 纯命令行 JUnit 最小环境

不使用 IDE、Maven 或 Gradle。需要 JDK，本次使用本机 Microsoft OpenJDK 17.0.18。

## 本目录内容

- [Calculator.java](Calculator.java)：业务代码，不依赖 JUnit。
- [CalculatorTest.java](CalculatorTest.java)：原来的手动测试，main 显式调用测试方法，保留用于对照。
- [CalculatorJUnitTest.java](CalculatorJUnitTest.java)：JUnit 测试类，没有 main，使用 `@Test` 与 `assertEquals`。
- [JUnit 独立运行包](lib/junit-platform-console-standalone-1.14.1.jar)：包含 Jupiter 5.14.1 API、测试引擎及 Platform 1.14.1 命令行入口等依赖。版本固定以便复现，不表示最新版。

## 从 GitHub 克隆后的首次依赖准备

仓库按既有规则忽略 JAR 与 class，不上传第三方二进制或编译产物。克隆后先进入此目录执行下面的 PowerShell 命令（已在本机下载过则不必重复）。若克隆路径不同，请调整 cd；固定 SHA-256 为本轮下载校验所得。

```powershell
cd D:\Learning\Java\examples\03-unit-test
$ErrorActionPreference = 'Stop'
New-Item -ItemType Directory -Path lib -Force | Out-Null
$url = 'https://repo.maven.apache.org/maven2/org/junit/platform/junit-platform-console-standalone/1.14.1/junit-platform-console-standalone-1.14.1.jar'
Invoke-WebRequest -Uri $url -OutFile 'lib/junit-platform-console-standalone-1.14.1.jar'
$actual = (Get-FileHash 'lib/junit-platform-console-standalone-1.14.1.jar' -Algorithm SHA256).Hash
if ($actual -ne 'A09C656D60ADA792CF12ED1E8DC7EAD3EDC98DDE034332E97DFCB5B4268B9072') {
    throw 'JUnit JAR 校验失败，请勿运行'
}
Write-Output 'JUnit 依赖准备完成'
```

## 编译和运行

以下命令用于 PowerShell；整个代码块可以一次粘贴。编译失败时会停止，不会继续运行旧字节码。

```powershell
cd D:\Learning\Java\examples\03-unit-test
javac -encoding UTF-8 -cp '.;lib/junit-platform-console-standalone-1.14.1.jar' -d out Calculator.java CalculatorJUnitTest.java
if ($LASTEXITCODE -ne 0) { throw '编译失败，请先修复编译错误' }
java '-Dfile.encoding=UTF-8' -jar lib/junit-platform-console-standalone-1.14.1.jar execute --class-path out --select-class CalculatorJUnitTest --fail-if-no-tests --disable-ansi-colors --details-theme ascii
```

成功时报告应包含 `2 tests found`、`2 tests successful`、`0 tests failed`。没有发现测试不是通过：`--fail-if-no-tests` 会让这种情况以非零状态退出。

首次下载完成后，编译和运行不需要联网。不需要修改全局环境配置。若终端找不到 java 或 javac，可用本机完整工具路径：`D:\ProgrameFiles\JDK\ms-17.0.18\bin\java.exe` 与同目录的 `javac.exe`，PowerShell 调用带引号的路径时在前面加 `&`。

## 命令分别做什么

编译时的 `-cp` 让 javac 找到 JUnit 注解与断言类型。Windows 类路径用分号分隔，因此整个参数加引号。`-d out` 把新字节码放到 out，避免与根目录的原始手动测试字节码混用。

运行时的 `java -jar` 启动 JUnit JAR 内提供的入口，而不是启动我们的测试类。`execute` 要求执行测试；其后的 `--class-path out` 是传给 JUnit 的参数，让它找到我们的字节码；`--select-class` 明确选中这个测试类。JUnit 通过 Jupiter 引擎识别 `@Test`，组织调用并汇总结果。

`assertEquals(5, actual)` 的第一个参数是预期值，第二个是实际值。框架只执行比较，不负责判断预期值是否符合业务规则。

## 保留的手动测试

仍然可以运行原来的 main 版本，两种示例互不替换：

```powershell
cd D:\Learning\Java\examples\03-unit-test
javac -encoding UTF-8 Calculator.java CalculatorTest.java
if ($LASTEXITCODE -ne 0) { throw '编译失败，请先修复编译错误' }
java '-Dfile.encoding=UTF-8' -cp . CalculatorTest
```
