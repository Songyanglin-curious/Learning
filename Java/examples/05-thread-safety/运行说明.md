# 运行线程安全实验

## 观察 volatile 如何发布数据

在 PowerShell 中运行下面的命令。

```powershell
Set-Location 'D:\Learning\Java\examples\05-thread-safety'
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
java '-Dfile.encoding=UTF-8' VolatilePublication.java
```

预期输出是 `读到 ready = true，data = 100`。

主线程先写 `data = 100`，再写 `ready = true`。读线程循环检查 `ready`，读到 `true` 才读取 `data`。同步关系由对同一个 `volatile ready` 的写入和读取建立。`Thread.onSpinWait()` 只是向 JVM 提示当前线程正在循环等待。

在这个例子里，只要先写数据、再写标志，读线程看到标志为 `true` 后就一定能读到 `100`。如果交换写入顺序，读线程就可能在 `data = 100` 之前读到旧值 `0`。这个实验用来观察正确写法的结果。

## 对比两个线程都读到 0 的次数

在 PowerShell 中执行以下命令。

```powershell
Set-Location 'D:\Learning\Java\examples\05-thread-safety'
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
java '-Dfile.encoding=UTF-8' VolatileReadComparison.java
```

每轮开始时，`x` 和 `y` 都是 0。一个线程先写 `x = 1` 再读 `y`，另一个线程先写 `y = 1` 再读 `x`。先用普通字段跑 30,000 轮，再用两个 `volatile` 字段跑 30,000 轮。两版的屏障都放在读写操作的前后，用于划分轮次。

本机 JDK 17 的一次运行中，普通版有 1,596 次两边都读到 0，具体次数随运行变化。两个字段都声明为 `volatile` 时，两边同时读到 0 的结果被 Java 内存模型禁止。

## 运行其他实验

在 PowerShell 中执行以下命令，使用 JDK 17 或更高版本。

```powershell
Set-Location 'D:\Learning\Java\examples\05-thread-safety'
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
# 丢失更新
java '-Dfile.encoding=UTF-8' LostUpdate.java

# 坐标中间状态
java '-Dfile.encoding=UTF-8' PartialPosition.java

# 可见性与有序性
java '-Dfile.encoding=UTF-8' Visibility.java
```

- **丢失更新**：两个线程都读取到 0，再分别写回 1，所以最终的 `count` 是 1。
- **中间状态**：读线程在两次坐标更新之间读取，得到 `(100, 0)`。
- **可见性与有序性**：每版运行 1,000 轮。`ready` 为 `false` 时，本轮跳过 `data`。普通版即使从未读到 0，也无法据此证明写入顺序对读线程可见。使用 `volatile` 的版本只要读到 `ready == true`，就保证随后读到 `data == 100`。
