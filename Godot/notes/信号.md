# 信号：事件通知与解耦

2026-11-17 整理；Godot 4.x。信号单元已随渐进式教程收束，本笔记保存可复用认识，不表示已独立掌握。

## 核心模型

信号是节点在特定事件发生时发出的通知，等价于 C# 事件 / 观察者模式。三个角色：发射方（节点）、信号本身（通常用过去时动词命名）、接收方（订阅并提供回调）。

价值是解耦：发射方不需要引用接收方，接收方也不需要知道通知来自谁。这比“每帧去问对方状态”更松耦合，也比硬编码互相引用更灵活。

## C# 写法

内置信号以 C# event 形式暴露，用 `+=` 订阅、`-=` 取消：

```csharp
button.Pressed += OnTogglePressed;
```

自定义信号用 `[Signal]` 声明委托，**名字必须以 `EventHandler` 结尾**，生成的事件名自动去掉该后缀：

```csharp
[Signal]
public delegate void HealthDepletedEventHandler();
```

发射用 `EmitSignal(SignalName.X, args...)`，**不能用 `Invoke`**。新增自定义信号后需重新构建，编辑器才能看到。

## 两种连接方式

| | 编辑器连接 | 代码连接 |
| --- | --- | --- |
| 连接记录在哪 | 写进 .tscn 的 `[connection]` 段 | 运行时内存，不写场景 |
| 回调来源 | 编辑器弹窗自动生成 | 手写 |
| 建立时机 | 场景加载时恢复 | `_Ready` 等执行时 |
| 适合 | 场景内固定节点、快速原型 | 运行时实例化、批量/条件连接 |

两者运行时行为一致，区别只在连接存放位置与建立时机。C# 项目实践中代码连接居多（经验倾向，非统计）：类型安全、重构友好、动态节点必须代码、diff 可读。

## 与帧处理的关系

信号回调不经过 `_Process`。`SetProcess(false)` 关掉帧更新后，按钮 `pressed` 仍会触发——这正好区分“帧更新通道”与“事件通道”。`SetProcess`/`IsProcessing` 定义在 Node，详见[脚本与帧更新笔记](CSharp脚本与帧更新.md)。

## 断连与释放（按需深入）

Godot 对象释放时通常自动断连相关连接。已知例外：lambda 捕获变量、自定义信号用 `+=` 连接时，可能不自动断连，需手动 `-=` 或用 `Connect`。本项目尚未展开验证，实际做动态创建/销毁时再查官方说明，不据此泛化。

## 证据与接续

信号示例已落地到 `D:\Game\脚本`：script.tscn 增加 ToggleButton(Button)，SpinDemo.cs 增加 `_Ready` 中 `GetNode<Button>("../ToggleButton")` 订阅 `Pressed += OnTogglePressed`，回调用 `SetProcess(!IsProcessing())`。`dotnet build` 0 错误，`--headless` 加载无报错；GUI 点击效果尚未由用户确认。用户自述理解信号概念，不据此认定独立应用。
