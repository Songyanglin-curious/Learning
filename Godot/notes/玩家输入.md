# 玩家输入：动作映射、状态查询与事件

2026-11-17 整理；Godot 4.x。记录玩家输入单元的两种处理方式与边界，不表示已独立实践。

## Input Map：动作与物理输入的映射

动作是语义名（如 ui_left），不是具体键名。Input Map 把键盘、手柄等输入绑定到动作；脚本按动作名处理，换绑定不需改逻辑。项目自带 ui_left/ui_right/ui_up 等动作，可在「项目 → 项目设置 → 输入映射」查看或修改。

引擎负责收集输入并维护动作状态；脚本决定动作代表什么行为。

## 状态查询（轮询）

`Input.IsActionPressed("ui_left")` 立即返回该动作现在是否按住，不等待按键、不注册监听、不消耗事件。按住期间多次查询都是 true；松开后变 false。

典型用法是在 `_Process(double delta)` 中每帧查询：

```csharp
if (Input.IsActionPressed("ui_left"))
{
    RotationDegrees -= DegreesPerSecond * (float)delta;
}
```

引擎每帧调用 _Process，脚本每帧主动读一次状态；持续按住就每帧转一小段。适合连续控制（转向、持续移动）。

`IsActionJustPressed` 只在刚按下那一下为 true，适合触发一次的行为（切换、跳跃等）；按具体 API 语义使用，不把“持续状态”与“刚按下”混用。

## 事件回调（通知）

引擎在输入事件到来时调用 `_Input(InputEvent e)`（或 `_UnhandledInput`），脚本检查事件本身：

```csharp
public override void _Input(InputEvent e)
{
    if (e.IsActionPressed("ui_left"))
        GD.Print("收到左转按下事件");
}
```

- `Input.IsActionPressed(...)`：问“现在还按着吗”。
- `e.IsActionPressed(...)`：问“传进来的这一次事件是这个动作的按下吗”。

事件是状态发生变化的通知；状态在两次事件之间保持不变。键盘长按可能产生重复按键事件，但那不是游戏的每帧更新。若只在按下事件里做一次性处理，不能等同于按住期间每帧处理。需要按住标记时可自行维护，但本例直接查询 Input 已维护的状态更省事。

## 状态 vs 事件的核心

事件回答“发生了什么变化”，状态回答“现在是什么”。一次按下，引擎记录状态；每帧查询读的是同一状态，直到松开。

## 转向与朝向前进示例

给 Sprite2D 的脚本（类名与文件名一致）：

```csharp
using Godot;

public partial class SpinDemo : Sprite2D
{
    [Export] public float DegreesPerSecond { get; set; } = 180.0f;
    [Export] public float MoveSpeed { get; set; } = 200.0f;

    public override void _Process(double delta)
    {
        float direction = 0.0f;
        if (Input.IsActionPressed("ui_left"))  direction = -1.0f;
        if (Input.IsActionPressed("ui_right")) direction = 1.0f;

        RotationDegrees += DegreesPerSecond * direction * (float)delta;

        Vector2 velocity = Vector2.Zero;
        if (Input.IsActionPressed("ui_up"))
            velocity = Vector2.Up.Rotated(Rotation) * MoveSpeed;

        Position += velocity * (float)delta;
    }
}
```

要点：
- Godot 2D 默认 Y 增大向下，Vector2.Up 是 (0,-1)。
- Rotated(Rotation) 把向上向量转到图片当前朝向；Rotated 需要弧度，所以传 Rotation，不是 RotationDegrees。
- 速度单位约为父坐标空间的像素/秒，乘 delta 得到本帧位移。
- 两个独立 if 使同时按左右时右侧覆盖；这是脚本规则，非引擎强制。

## 边界

本例直接改 Sprite2D 的角度与位置，不经过碰撞移动，画面里有墙也可能穿过；这不等价于物理失效。物理对象选型与控制权问题见[职责边界笔记](引擎与脚本的职责边界.md)。运行画面需有键盘焦点才能收到输入。

## 证据与接续

用户自述已理解状态查询与事件通知的区别，输入子单元按其反馈收束；输入版脚本尚无实际保存/构建/运行反馈，不据此认定移动与输入实践完成。后续自然接信号（碰撞、按钮等事件通知），或回生命周期主线的构造、入树、就绪边界。
