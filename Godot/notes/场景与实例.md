# 场景、运行入口与实例覆盖

本笔记整理已收束的入门概念，供后续查阅；不是能力验收报告。适用 Godot 4.x，整理于 2026-11-17。

## 节点与场景：运行的是什么？

节点是具有特定能力的对象：Label 显示文字，Sprite2D 显示图片，CollisionShape2D 描述供物理对象使用的碰撞形状。节点可组成父子树；父子关系不是 C# 类型继承。对 Node2D/Control 等画布节点，变换通常沿父子关系传递，特殊顶层设置等另论。

场景保存一套以单个根节点组织的节点结构，以及属性、脚本和资源引用。文本场景通常保存为 `.tscn`。文件是结构描述，运行实例才是实际对象。场景可以代表球、玩家、菜单、关卡，不只代表完整画面或关卡。

## 主场景与当前场景

- F5：使用项目配置中的主场景作为默认入口，可类比 Main 指定的启动内容。
- F6：临时从当前编辑场景的根节点启动整场景，不是从场景树中选中的节点开始。

两者都是正常的引擎运行，脚本、物理、声音等照常执行，不是把一份临时配置仅作渲染。当前场景内部实例化的其他子场景同样参与运行。

场景可以组合（关卡、玩家、敌人和 HUD 的实例同时存在），也可以切换（菜单切到关卡）。主场景只是默认入口，不必永远存在，也不必承担所有协调逻辑。

## 独立场景与实例化

分别创建或复制得到的独立场景，没有自动联动关系。两处都使用 Label 类型，不表示它们是同一个对象或引用同一模板。

实例化是从同一场景模板创建一整套节点。一个球场景包含根节点、图片节点和碰撞形状节点时，实例化五次就得到五套节点。它与代码中的对象实例化概念相通，但创建的粒度可以是整棵树。

编辑器保存的场景实例还保留源场景关联，区别于普通 C# 对象创建后不自动跟随某个模板对象变化的行为。此关联不代表运行中的对象会自动热更新；修改默认值的讨论主要针对编辑器保存结构及后续实例化。

## 源默认值、实例覆盖与恢复

源场景提供默认属性值。实例中未覆盖的属性可跟随源场景修改；在实例上覆盖的属性保留本级值。覆盖按属性生效：位置不同，并不妨碍文字继续跟随源场景。

例：两个实例都引用同一 Label 场景。

1. 改源场景的 Text 并保存，未覆盖该属性的实例更新。
2. 只给其中一个实例设置自己的 Text，此实例形成局部覆盖。
3. 再改源 Text，该实例保留自己的文字，另一个继续跟随。
4. 使用属性旁的恢复箭头取消覆盖，重新使用源值。需要恢复关联时使用明确的恢复操作，不依赖手动填入相同文字判断覆盖是否已清除。

这与“继承上级默认值、本级自定义、重置恢复继承”的配置机制相通，不是 C# 类继承，也不等同于 Godot 单独提供的场景继承工作流。

## 节点独立与资源独立是两回事

不同实例的节点是不同对象，但图片、形状、材质等资源可能被多个节点引用。不能推断实例化一定深拷贝所有资源。具体共享、Make Unique、嵌套复制及 Local To Scene 的规则留到真实问题时核对，不从本笔记推导通用深拷贝保证。

## 编辑器防误选

选中墙体父节点后，用 2D 工具栏锁头旁的“将所选节点与子节点分组”功能，可使在画布中点击子节点时选中父节点；需要单独编辑时仍可从场景树选子节点。它解决选择问题，不新增父子关系，不是运行时 Groups，也不同于防止误操作的锁定功能。
