## 学习目标与方式

围绕文件、数据与读写过程，建立能够理解、判断和使用 Java IO 的能力。先知道有哪些能力，再理解读写时发生了什么，最后补充原理与特殊用途。

- 每次只推进一个小问题，控制单次信息量，不一次讲完整章。
- 重点理解运行机制、核心语义、适用边界和方案权衡；常规 API 与配置按需查阅，不要求逐项记忆。
- 结合已有 C# 基础解释共通概念，把重点放在 Java 的规则和容易误判的地方。
- 从数据在哪里、对象负责什么、调用后发生什么入手，再引入术语。
- 有疑问时构造最小实验，以实际运行结果检验理解；不为每个知识点固定安排练习，生成的代码本身不作为正确性证据。
- 同一个问题最多深入两轮；仍未解决时先记录待办与后续步骤。
- 理解稳定后再整理知识笔记；本文件记录计划与接续位置，明确区分已讨论内容与尚未展开的内容。
- 对已有文件操作经验能够直接理解的常规 API，只需说明用途与行为边界，不逐项展开讲解。
- 场景只用于解释 Java 能力与机制，不默认延伸到业务配置、部署架构或无边界的设计经验讨论。
- 解释异常等机制时，先说明问题怎样产生，再说明怎样处理，最后解释处理规则的理由。
- 对简单数据传输，围绕明确的数据类型和常规转换使用学习；复杂对象恢复机制作为边界认识，不套成所有日常 JSON 使用的复杂度。

## 三条学习主线

### 一、文件与路径：先分清角色

涉及 `File`、`Path`、`Files`，围绕以下问题逐步展开：

- 表示文件位置、操作文件与读取文件内容有什么区别？
- 相对路径依赖什么，为什么同一段代码可能找到不同位置？
- `File` 与 `Path` 各自表示什么，`Files` 提供哪些能力？
- 检查存在、创建目录、复制和移动等操作，分别解决什么需求？

目标：能够区分路径对象、实际文件和打开后的读写资源，并能为常见文件操作选择入口。

### 二、数据读写：理解字节与文字的关系

涉及 `InputStream`、`OutputStream`、`Reader`、`Writer`，围绕以下问题逐步展开：

- 输入与输出的方向以谁为参照？流提供了什么读写模型？
- 字节流与字符流分别适合什么数据？
- 字节怎样按编码变成文字，文字怎样编码后写出？
- 一次性读取与分批处理分别适合什么场景？

目标：能够按数据性质选择读写方式，理解编码发生的位置，以及整份加载对内存的要求。

### 三、读写过程：理解行为与资源边界

围绕实际读写中的问题理解缓冲、包装、关闭与异常：

- 一次读取返回的数量表示什么，怎样判断结束，为什么可能读不满？
- 缓冲解决什么问题，包装流与底层流各自负责什么？
- `flush` 与 `close` 分别做什么，写入调用返回意味着什么？
- 谁负责关闭资源，`try-with-resources` 怎样组织正常与异常路径？

目标：能够理解常见读写代码的数据流和资源归属，识别读取数量、缓冲和关闭方面的陷阱。底层实现与性能调优在出现具体疑问时再深入。

### 本轮建立的判断

- 路径描述位置，实际操作访问文件系统，资源流提供数据；三者不混为同一对象。
- 字节是输入输出的数据单位，文字需要按编码解释；分批处理还需要维护解码状态。
- 流提供逐步读写能力，内存需求还取决于结果、缓存、队列和对象引用怎样保留数据。
- 读取容量与实际数量不同；`-1` 表示相应流或当前 ZIP 条目的末尾，不表示暂时没数据。
- 缓冲与包装各有分工；`write` 返回、刷新到下层、对其他进程可见、可靠落盘是不同保证。
- 生命周期由明确的责任方管理；自动关闭会尝试释放资源，但不保证外部 IO 成功，也不回滚已完成操作。
- 格式本身与工具附加的恢复能力不同；原生对象序列化的复杂度不能全部归到普通 JSON。
- 常规 API 可按需查阅，遇到实际问题再做最小实验，不把生成的示例代码当作行为验证。
